# Политика конфиденциальности Anixart Desktop

Редакция от 27 ноября 2026 г.

## 1. Область действия

Anixart Desktop — независимый неофициальный клиент Anixart для Windows и macOS. Разработчик проекта MurrRchalka распространяет готовые сборки бесплатно через [GitHub](https://github.com/MurrRchalka/Anixart/releases); исходный код находится в закрытом репозитории.

Настоящая политика описывает обработку данных самим Desktop и взаимодействие с внешними сервисами. Она не заменяет [политику конфиденциальности Anixart](https://anixart-app.com/privacy), не является согласием, предоставляемым администрации Anixart, и не регулирует самостоятельную обработку данных сторонними сервисами. При использовании Anixart применяются также его [пользовательское соглашение](https://anixart-app.com/terms), [правила сообщества](https://anixart-app.com/rules) и, при необходимости, [согласие на обработку данных](https://anixart-app.com/consent) и [согласие на распространение данных](https://anixart-app.com/consent-dissemination).

## 2. Авторизация и учётная запись

- При входе по логину или электронной почте введённый идентификатор и пароль передаются API Anixart для проверки. При регистрации и восстановлении доступа передаются необходимые данные формы, включая электронную почту, пароль и проверочные коды. Пароль не предназначен для постоянного хранения в Desktop.
- При выборе входа через QR-код или внешнего поставщика (Google, ВКонтакте, Telegram, Яндекс — при доступности соответствующего способа) обрабатываются данные и временные коды, необходимые для подтверждения личности и получения сессии Anixart. Авторизация может использовать браузер или отдельное окно и локальный механизм возврата результата. Поставщик обрабатывает данные согласно собственным условиям.
- Идентификатор аккаунта и токен сессии Anixart сохраняются средствами операционной системы: в диспетчере учётных данных Windows или связке ключей macOS. Интерфейс использует непрозрачный идентификатор сессии; собственно токен применяется нативным сетевым модулем. Предусмотрен перенос токена из старого локального хранилища с удалением устаревшей записи после успешного переноса/входа. При ошибке защищённого хранилища может потребоваться повторить операцию.
- Для подсказок при следующем входе в локальном хранилище WebView могут сохраняться логины и адреса электронной почты до пяти последних аккаунтов. Эти подсказки не содержат паролей и могут оставаться после выхода из аккаунта.
- При восстановлении сессии и работе с сервисом загружаются данные профиля. Изменения профиля, аватара, настроек приватности, списков, закладок, оценок, истории просмотров, комментариев и других доступных функций передаются Anixart при выполнении соответствующих действий. Данные, публикуемые пользователем, могут быть видимы другим пользователям согласно правилам сервиса и настройкам приватности.

## 3. Локальное хранение и кэш

Приложение использует память процесса, локальное хранилище WebView и файлы в каталогах данных и кэша приложения. В зависимости от функций и настроек могут сохраняться:

- настройки интерфейса, гостевого режима, воспроизведения, выбранного источника и озвучки, параметров обновлений и состояния интерфейса;
- история поиска, локальные сведения о просмотре и выборе видео, необходимые для продолжения воспроизведения и работы с источниками;
- загруженные карточки, списки, ответы API, изображения, анимации и служебные сведения для ускорения повторных запросов;
- служебные правила блокировки рекламы, информация о сетевых маршрутах и загруженные файлы обновлений.

Постоянный кэш данных разделяется по области доступа и имеет ограничения по объёму и сроку хранения; в реализации предусмотрена фильтрация чувствительных полей. Это не означает, что весь кэш зашифрован или что он не содержит сведений о пользователе. Настройки и история могут сохраняться между запусками до изменения или очистки. Встроенный браузер и внешние сайты могут отдельно сохранять cookies, HTTP-кэш и другие данные сайтов в соответствии с поведением WebView и браузера.

При экспорте закладок файл записывается в выбранное пользователем место. Импорт обрабатывает выбранный файл и может отправлять необходимые изменения в Anixart. Экспортированные файлы и данные, сохранённые сторонними приложениями, управляются отдельно.

## 4. Сетевые запросы и получатели данных

Для получения каталога, профиля, синхронизации и выполнения пользовательских действий Desktop обращается к API Anixart, включая поддерживаемые сетевые адреса сервиса. При выборе альтернативного соединения могут запрашиваться конфигурация доступных адресов и результаты проверок соединения; для обнаружения адресов используются в том числе публичные ресурсы GitHub Pages.

В зависимости от используемой функции получателями запросов являются:

- Anixart и его инфраструктура — сведения, необходимые для выполнения запроса, в том числе данные авторизации при обращении к защищённым функциям, поисковые запросы, идентификаторы релизов и действия пользователя;
- поставщики авторизации Google, ВКонтакте, Telegram, Яндекс и их инфраструктура — данные соответствующей процедуры входа;
- сторонние каталоги и видеоисточники (например, YummyAnime, Kodik, AniLiberty/Libria, Sibnet, Alloha, Aksor, Rutube), их CDN и ресурсы изображений — данные поиска/сопоставления релиза, адреса видео, сведения о запросах медиапотоков, доступности и воспроизведении;
- GitHub и его CDN — запросы документации, метаданных обновлений и загрузки сборок; поставщики списков блокировки рекламы, включая EasyList/EasyPrivacy и RU AdList, — запросы обновления правил;
- при использовании резервного DNS для видео — Google Public DNS и/или Cloudflare, которым могут передаваться имена запрашиваемых доменов; при открытии внешних ссылок — сайты, выбранные пользователем.

При сетевом взаимодействии получатель может видеть IP-адрес, время обращения, технические заголовки, сведения о клиенте, запрашиваемые адреса и другие параметры, необходимые для обработки запроса. Веб-плееры могут выполнять сторонние скрипты и использовать cookies; блокировка рекламы ограничивает часть запросов, но не гарантирует отсутствие рекламы, отслеживания или передачи данных. Внешний плеер получает адрес и необходимые параметры воспроизведения при его запуске. Desktop не управляет политиками хранения данных этих получателей; данные могут обрабатываться за пределами страны проживания пользователя.

## 5. Диагностика, телеметрия и обновления

В приложении предусмотрены локальная диагностика сетевых операций, авторизации, загрузки интерфейса и воспроизведения, в том числе сообщения в консоли и стандартном выводе процесса. Диагностика может включать этапы операций, коды HTTP/API, длительность и технические ошибки. В отдельных механизмах используются ограниченные наборы полей и маскирование секретов; это не гарантирует отсутствие чувствительных сведений во всех системных журналах.

В текущей проверенной реализации не предусмотрена отдельная автоматическая отправка разработчику Desktop аналитики использования или отчётов о сбоях. Обычные запросы к внешним сервисам, включая проверку обновлений при запуске, обновление списков блокировки и фоновые проверки доступности видео, не следует считать отсутствием сетевой активности или гарантией отсутствия журналирования у получателей.

Форма сообщения об ошибке создаёт черновик локально. Версия приложения, сведения об ОС и вручную введённый фрагмент журнала включаются по выбору пользователя. Черновик может быть скопирован и отправлен пользователем самостоятельно; автоматической отправки этой формой нет. Перед отправкой необходимо проверить текст, даже если приложение выполнило маскирование.

## 6. Цели обработки, защита и сроки

Данные используются для входа и сохранения сессии, предоставления функций сервиса, синхронизации, воспроизведения, локальных настроек, ускорения работы, диагностики и получения обновлений. Данные, необходимые для запроса, обрабатываются в связи с выбранной пользователем функцией. Отдельные согласия, необходимые оригинальному сервису, регулируются его документами.

Используются защищённое системное хранилище сессии, разграничение доступа к кэшу и предусмотренные сетевыми протоколами меры защиты. Ни один способ обработки и хранения не обеспечивает абсолютной безопасности. Не передавайте свои пароли, токены, журналы или файлы с конфиденциальными сведениями третьим лицам.

Сроки хранения локальных данных зависят от их назначения: временные данные используются в ходе работы, сессия сохраняется для повторного входа, настройки и подсказки могут сохраняться до очистки, а постоянный кэш удаляется по лимитам, сроку хранения или команде пользователя. Сроки хранения данных у Anixart и других получателей определяются ими самостоятельно.

## 7. Управление данными и права пользователя

- Выход из учётной записи прекращает локальную сессию и предусматривает удаление сохранённого токена. Если приложение сообщает об ошибке удаления, повторите выход. Это не удаляет профиль на сервере Anixart.
- В разделе «Данные и память» можно управлять кэшированием данных и изображений и очищать кэш. Очистка кэша не равнозначна удалению всех настроек, истории поиска, сохранённых подсказок, cookies или данных аккаунта.
- Для полного удаления локальных данных необходимо выйти из аккаунта, закрыть приложение, удалить его данные средствами ОС, при необходимости проверить системное хранилище учётных данных и данные браузера, а также самостоятельно удалить ранее экспортированные файлы. Одно удаление программы не гарантирует удаления всех этих данных.
- Для изменения или удаления данных на серверах Anixart используйте настройки профиля, [порядок удаления аккаунта](https://anixart-app.com/profile-delete) и [официальную поддержку](https://anixart-app.com/contact). Для данных иных сервисов обращайтесь к соответствующему поставщику.

Пользователь вправе обращаться за разъяснениями, исправлением и удалением данных в пределах применимого законодательства и компетенции соответствующего обработчика. В отношении сведений, добровольно переданных разработчику Desktop при обращении, они используются для рассмотрения обращения; для публичных публикаций и сообщений также действуют условия площадки.

## 8. Связь и изменения политики

По вопросам обработки данных непосредственно Desktop можно обратиться к разработчику через [репозиторий релизов](https://github.com/MurrRchalka/Anixart) или его [раздел Issues](https://github.com/MurrRchalka/Anixart/issues). Раздел Issues публичен: не размещайте там персональные данные, токены, пароли или необработанные журналы; при необходимости запросите безопасный способ связи. По вопросам данных Anixart обращайтесь к администрации оригинального сервиса.

Актуальная редакция политики доступна по [постоянному адресу](https://github.com/MurrRchalka/Anixart/blob/main/PRIVACY.md). Политика может уточняться по мере изменения функциональности. Связанный документ: [пользовательское соглашение Anixart Desktop](TERMS.md).
